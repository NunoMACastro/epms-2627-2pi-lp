# Ficha de exercícios: DML e consultas com contexto

Praticas as consultas com o `WHERE`, o `ORDER BY` e o `LIMIT`, e as mudanças dos dados, numa transação quando as queres poder desfazer. Os exercícios 1 a 6 são obrigatórios. Trabalhas no servidor do laboratório, na base `torneio` da ficha do tema 02. Nos exercícios 1 a 4, escreves uma consulta para cada pergunta. As consultas e os comandos ficam no `torneio-perguntas.sql`, na pasta do projeto, cada um com um comentário com a pergunta. Para rever: o [guia do tema](../03-dml-e-consultas-com-contexto.md) e o [laboratório](../laboratorios/03-dml-e-consultas-com-contexto-laboratorio.md).

## O cenário

O torneio da ficha do tema 02 cresceu: agora tem quatro equipas, oito jogadores e sete partidas. As tabelas são as da ficha do tema 02, neste `torneio.sql`:

```sql
-- torneio.sql: as tabelas da base torneio, com as regras do torneio.
-- Corre-se no psql, ligado à base torneio, com \i torneio.sql.

-- Apaga as tabelas, se existirem. As partidas e os jogadores apontam para as
-- equipas, por isso apagam-se antes delas.
DROP TABLE IF EXISTS partidas;
DROP TABLE IF EXISTS jogadores;
DROP TABLE IF EXISTS equipas;

-- As equipas. O nome é obrigatório e não se repete.
CREATE TABLE equipas (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(30) NOT NULL UNIQUE
);

-- Os jogadores. O nome no jogo é único; o nome verdadeiro pode repetir-se.
CREATE TABLE jogadores (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome_no_jogo VARCHAR(20) NOT NULL UNIQUE,
    nome_verdadeiro VARCHAR(50) NOT NULL,
    equipa_id INTEGER NOT NULL REFERENCES equipas (id)
);

-- As partidas. Os pontos e a duração ficam sem valor enquanto a partida não acaba.
CREATE TABLE partidas (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    data DATE NOT NULL,
    equipa_casa_id INTEGER NOT NULL REFERENCES equipas (id),
    equipa_fora_id INTEGER NOT NULL REFERENCES equipas (id),
    -- Um CHECK deixa passar o NULL: a partida marcada entra sem pontos.
    pontos_casa INTEGER CHECK (pontos_casa >= 0),
    pontos_fora INTEGER CHECK (pontos_fora >= 0),
    -- A duração, em minutos, só se sabe quando a partida acaba.
    duracao INTEGER CHECK (duracao >= 1 AND duracao <= 90),
    -- Uma equipa não joga contra si própria.
    CHECK (equipa_casa_id <> equipa_fora_id)
);
```

E os dados são estes, no `torneio-dados.sql`:

```sql
-- torneio-dados.sql: os dados do torneio, com quatro equipas, oito jogadores e sete
-- partidas. Corre-se depois do torneio.sql, com \i torneio-dados.sql.

    ('Raposas'),     -- 1
    ('Tubarões'),    -- 2
    ('Lobos'),       -- 3
    ('Águias');      -- 4

    ('ritaxx', 'Rita Matos', 2),         -- 1
    ('kiko', 'Francisco Lopes', 1),      -- 2
    ('zeca', 'José Costa', 3),           -- 3
    ('lobo1', 'Leo Brás', 3),            -- 4
    ('raio', 'Inês Faria', 1),           -- 5
    ('sombra', 'Tiago Neves', 4),        -- 6
    ('rexy', 'Rúben Silva', 2),          -- 7
    ('nina', 'Carolina Dias', 4);        -- 8

-- As partidas por jogar ainda não têm pontos nem duração.
INSERT INTO partidas (data, equipa_casa_id, equipa_fora_id, pontos_casa, pontos_fora, duracao) VALUES
    ('2026-12-05', 1, 2, 13, 9, 60),          -- 1, Raposas contra Tubarões
    ('2026-12-12', 2, 1, NULL, NULL, NULL),   -- 2, Tubarões contra Raposas, por jogar
    ('2026-12-05', 3, 4, 7, 7, 90),           -- 3, Lobos contra Águias
```

Troca o conteúdo do teu `torneio.sql` e do teu `torneio-dados.sql` pelos destes dois blocos. Se ainda não tens a base `torneio`, cria-a com `CREATE DATABASE torneio;`. Entra nela e corre os dois ficheiros, por esta ordem. Os resultados esperados dos exercícios 1 a 4 são os da base acabada de construir; o exercício 5 muda-a.

## Exercício 5: O resultado de uma partida

A partida de 12 de dezembro, Tubarões contra Raposas, acabou 8 a 11, com a vitória das Raposas, e durou 75 minutos. Guarda o resultado na base. Escreve no `torneio-perguntas.sql` a consulta que mostra a linha antes da mudança e o comando que a muda.

| Comando | Resultado esperado |
| --- | --- |
| A tua consulta, antes da mudança | 1 linha: Tubarões contra Raposas, de 12 de dezembro, sem pontos |
| O teu comando | `UPDATE 1` |
| A tua consulta de antes, outra vez | A mesma partida, com os pontos e a duração |
| `SELECT * FROM partidas WHERE equipa_fora_id = 1 AND pontos_fora > pontos_casa;` | 2 linhas, as partidas que as Raposas venceram fora de casa: a 4 e a desta mudança |
| A consulta da pergunta 1 do exercício 3 | 2 linhas: as partidas 6 e 7 |

Rever: [O UPDATE muda as linhas que o WHERE escolhe](../03-dml-e-consultas-com-contexto.md#o-update-muda-as-linhas-que-o-where-escolhe) e [Antes de mudar, o mesmo WHERE num SELECT](../03-dml-e-consultas-com-contexto.md#antes-de-mudar-o-mesmo-where-num-select).
